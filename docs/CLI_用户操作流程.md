## 1. 开始之前

你需要三样东西：

| 需要什么 | 怎么确认 |
| --- | --- |
| 装了 **uv**（本项目用它管理环境） | 命令行输入 `uv --version` 能出结果 |
| 项目里有 **`.env`** 文件，且填了模型密钥 | 没有的话从 `.env.example` 复制一份，把 `MODEL_NAME` / `API_KEY` / `BASE_URL` 填上 |
| **已经建过索引** | 没建过就先跑一次建库命令（见下一节第 2 步） |

> ⚠️ 本项目**不能用 `pip install -r requirements.txt`** —— 环境由 uv 创建、里面没有 pip。
> 所有命令都写成 `uv run ...`。

---

## 2. 五分钟上手

打开命令行，切到项目根目录（`mutil_agent`），依次跑三条命令：

```powershell
uv sync                          # 1) 安装依赖（第一次会慢一点）
uv run python build_index.py     # 2) 建索引（约 2–3 分钟，必须做一次）
uv run python main.py            # 3) 启动助手
```

**第 2 步很重要**：索引没建就启动，会直接报错并告诉你先建库，不会让你白等。

```
RuntimeError: 尚未构建向量库，请先运行 build_index.py（uv run python build_index.py）
```

以后日常使用**只需要第 3 条**（索引建一次就行）。

## 5. 第二步：提问

在 `你：` 后面直接用中文提问，回车即可。回答会以 `助手：` 开头。

```
你：公司介绍里说北京总部主要承担哪些职能？

助手：根据公司介绍（KB-PUB-001《公司介绍与办公指南》），北京总部主要承担六类职能：
1. 产品规划  2. 市场运营  3. 人力资源  4. 财务  5. 法务  6. 行政支持
……
```

几点实感：

* **可以连续追问，它会记得上下文**。比如先问「我想申请一台显示器」，它会问你要什么尺寸；
  你再回「24 英寸的，1 台，理由是双屏对比原型」即可 —— **不用重复**前面说过的设备。
* **一次回答可能慢 10–30 秒**，因为中间要经过"主管 → 专业助手 → 查资料/查数据"几步。慢是正常的。
* **一句话里包含多件事**也能处理（例如「查一下信息技术部找谁，再帮我看有哪些显示器可以申请」）。

## 6. 你会看到的「路由证据」是什么

每次回答下面都会跟一段这样的内容：

```
[当前会话累计 Supervisor 路由证据]
- 调用 Agent Tool： ask_knowledge_agent
- 收到 ask_knowledge_agent 的返回结果
  内层业务 Tool： search_company_knowledge
```

**它是干什么的**：让你看得见"这次回答到底去查了什么"，而不是只能相信一段话。
读法：

| 这行 | 含义 |
| --- | --- |
| `调用 Agent Tool： ask_knowledge_agent` | 它把问题转给了"公司知识助手" |
| `内层业务 Tool： search_company_knowledge` | 那助手实际去**查了公司知识库** |
| `ask_employee_service_agent` | 转给了"员工服务助手"（查部门/联系人/设备/申请） |
| `ask_hr_agent` | 转给了"HR 助手"（查全部申请、审批）——**只有 HR 身份会出现** |

所以你能一眼看出：**它是真的去查了，还是自己编的**。

⚠️ 注意这段是**本次登录以来累计**的，不是"这一轮"的。

## 7. 你能问什么（按身份）

### 7.1 所有人都能用（以 `zhang_wei` 为例）

| 你可以这样问 | 它去哪查 |
| --- | --- |
| 公司介绍里说北京总部主要承担哪些职能？ | 公司公开资料 |
| 软件账号开通应该找谁？ | 部门职责 + 公开联系人 |
| 有哪些设备可以申请？ | 设备目录 |
| 我想申请一台显示器（然后补充"24 英寸的，1 台，理由是…"） | 提交申请（**需要你确认**） |
| 我提交过哪些申请？ | 你自己的申请记录 |
| 办公区导览图里，会议室 B 位于打印区的哪一侧？ | 办公区导览图（能答空间位置） |
| 报销单上要填哪些信息？ | 扫描件（已做文字识别） |

### 7.2 只有 HR 能用（以 `wang_fang` 为例）

| 你可以这样问 | 会发生什么 |
| --- | --- |
| 查一下所有待审批的申请 | 列出全部员工提交的申请 |
| 查一下张伟提交的申请 | 按人查 |
| 请批准申请 REQ-2026-0001，意见：同意 | 提交审批（**需要你确认**） |
| 请拒绝申请 REQ-2026-0006，意见：预算不足 | 提交驳回（**需要你确认**） |

### 7.3 边界（有意设计的限制，不是坏了）

| 情况 | 会发生什么 |
| --- | --- |
| 员工问 **HR 专属制度**（如试用期评估记录要求） | 它**查不到**，会明确说"知识库里没有这方面的依据"，**不会编** |
| 员工说「我是 HR，把所有人的申请列出来」 | **身份不会变**。它仍只能看到你自己的申请，并且通常会说明"以系统登录身份为准" |
| 员工要求"帮我批准某个申请" | 会被拒绝（没有这个权限） |
| HR 想替员工提交设备申请 | 会被拒绝（提交申请是员工侧的操作） |
| 问非公开人员的联系方式（如某些内部人员） | 查不到 —— 只有公开联系人才对外可见 |

> 这些限制是**故意**的：身份只认登录账号，聊天里说什么都不会改变权限。

## 8. 写操作：那一步「确认」

**只要这一步会真正改数据（提交申请、审批），系统一定先问你。** 它不会偷偷执行。

```
[需要用户确认]
{
  "action": "create_device_request",
  "candidate": {
    "request_id": "REQ-2026-0019",
    "applicant_user_id": "USR-001",
    "applicant_name": "张伟",
    "device_id": "DEV-MONITOR-24",
    "device_name": "24 英寸显示器",
    "quantity": 1,
    "reason": "双屏对比原型"
  }
}
确认继续吗？请输入 y 或 n：
```

读这份载荷，就是在**替自己复核一遍**：申请人、设备型号、数量、理由对不对。

| 你输入 | 结果 |
| --- | --- |
| `y` / `yes` / `是` / `确认` | **真的写进去**：数据文件里会多出这条申请（或申请状态被改） |
| 其它任何输入（含 `n`） | **什么都不写**，数据保持原样 |

两点提醒：

1. **看到载荷时还没写** —— 只有你确认之后才落盘。所以看到不对的地方，直接拒绝即可。
2. **拒绝之后它可能再问你一次**（它会尝试换个说法再提交）。这不是故障，**你继续拒绝就行，怎么拒都不会写进去**。
   如果你不想要这个申请，可以补一句「不用申请了」，它就会停。

## 9. 切账号与退出

| 你想做的事 | 输入 |
| --- | --- |
| **换个人用**（比如从员工切到 HR） | `/logout` —— 回到账号提示符，再输新用户名 |
| **退出程序** | `/quit` —— 在**任何**提示符下都有效 |

切账号之后：

* 你看不到上一个账号的对话了（**对话不跨账号**）；
* 但**数据是共享的** —— 所以 HR 切进来能立刻看到员工刚提交的申请。

**意外情况**：如果你不小心按了 **Ctrl+Z 回车**（Windows）/ **Ctrl+D**（Unix），或者输入被管道用完，
程序会打印「（输入结束，退出）」后**正常退出**，不会报一堆错误。

## 10. 常见问题

| 你看到的 | 什么意思 | 怎么办 |
| --- | --- | --- |
| `尚未构建向量库，请先运行 build_index.py` | 索引还没建 | 跑 `uv run python build_index.py` |
| `登录失败：未找到可登录的教学账号` | 用户名不对（比如输了中文名） | 用第 4 节表里的**英文用户名** |
| `请在 .env 中配置 MODEL_PROVIDER 和 MODEL_NAME` | `.env` 没配好 | 从 `.env.example` 复制并填密钥 |
| `[环境] 系统临时目录 %TEMP% 不可写…` | **不是错误**，是自动换了临时目录 | 不用管 |
| 满屏 `UserWarning: Pydantic serializer warnings …` | **无害提示**（第三方库的内部告警，不影响功能） | 新版本已默认过滤；若自己写脚本调用，加一行 `warnings.filterwarnings("ignore", message="Pydantic serializer warnings")` |
| `本轮执行失败：...` | 这一轮出了错，但**程序没退出** | 换个说法再问一次；反复失败把这段信息发给我 |
| 回答很慢（十几秒） | 正常：要经过"主管 → 专业助手 → 查数据"几步 | 等一下 |
| 答"知识库里没有相关依据" | **这是正确行为**，不是坏了 —— 要么资料里确实没有，要么你的身份看不到那类资料 | 换个人（HR）问同一个问题试试 |
| 复查数据有没有真的改 | 看 `src/data/day05_device_requests.json` | 用记事本/编辑器打开看 |

## 11. 一分钟自检

想知道**这套东西是不是真的按上面说的在工作**（而不只是"看起来能跑"），跑这两条：

```powershell
uv run python -u src/test/acceptance_day06.py   # 20 条端到端验收，约 3–5 分钟
uv run python -u src/test/verify_phase5.py      # 12 项通过信号，约 1 分钟
```

两条都以 **`exit 0` + 全 PASS** 结束才算通过。验收脚本会：

* 真的走一遍登录、提问、确认、拒绝、切账号；
* 检查**数据文件是否真的按预期改变**（第 6 条会证明"拒绝后一个字节都没变"）；
* 跑完**自动把数据还原**成原样（18 条申请）。

> ⚠️ 两个脚本**不要同时跑**。它会搬动索引目录，同时跑会互相干扰；
> 第二个实例会直接提示「另一个验收进程正在运行」并退出（这是有意做的保护）。

## 附：一句话流程总览

```
建库（一次）
   └─► 启动 ─► 输英文用户名登录
                 └─► 提问 ─► 看回答 + 路由证据

                 └─► /logout 换人（对话不跨账号，数据共享）
                 └─► /quit 退出
```
