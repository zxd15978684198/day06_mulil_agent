## 2. 设计令牌（`frontend/src/index.css`）

底座取自 `awesome-design-md` 的 `linear.app` 设计语言，**只取令牌层**。整套界面只有一条视觉规则：

> **深色底靠 `surface` 阶梯 + 1px 发丝边框分层，不用阴影。**

所以令牌表里**没有任何 `shadow-*`** —— 需要"浮起来"的地方一律用更高一阶的 surface 加一圈 hairline 表达。

| 组 | 令牌 | 值 | 用途 |
|---|---|---|---|
| surface 阶梯 | `--color-surface-0/1/2/3` | `#0b0c0e` / `#131417` / `#191b1f` / `#21242a` | 页面底 / 卡片 / 卡片内嵌 / 输入框与激活态 |
| 发丝边框 | `--color-hairline` / `-strong` | `#26282e` / `#34373e` | 普通分隔 / 强调分隔 |
| 文字四级 | `--color-ink-0/1/2/3` | `#f7f8f8` / `#b4b8bf` / `#8a8f98` / `#5c6069` | 主 / 次 / 弱 / 极弱 |
| 品牌 | `--color-accent` / `-hi` / `-soft` | `#5e6ad2` / `#6e79dd` / `#1f2140` | 主按钮 / hover / 徽章底 |
| 状态 | `--color-ok` `--color-warn` `--color-danger`（各带 `-soft`） | `#4cb782` `#d4a72c` `#e5484d` | 成功 / 警告 / 危险 |
| 圆角 | `--radius-control` / `--radius-card` | `7px` / `10px` | 控件 / 卡片 |
| 字体 | `--font-sans` / `--font-mono` | 含 `Microsoft YaHei`/`PingFang SC` 的中文栈 | 正文 / 编号类 |

无障碍：统一 `:focus-visible` 焦点环走 accent（不用浏览器默认蓝）；`color-scheme: dark`。

## 3. 登录页的三个设计决定

1. **演示账号必须点选可得**。后端**没有"列出用户"接口**，页面不写出来，演示时对方就卡在第一步。账号逐字取自 `src/data/day05_users.json`（共 10 个可登录，页面列 5 个：张伟/李娜/陈浩/王芳/郑凯），HR 账号带 accent 徽章区分。
2. **错误文案是中性**。因为后端把**一切**异常都映射成 `401 此用户不存在`（`agent_api.py:96-98`，已记为已知限制），网关故障时也会给 401，所以文案写成"账号不可用，或服务暂时异常"而不是武断的"账号不存在"。
3. **`App.tsx` 用 `loadSession()` 惰性初始化**，刷新时不会闪一下登录页；`R3` 的出口（404 → 清 localStorage 回登录页 + 顶部黄条提示）已经接好，P6 复用。

## 5. 偏差声明

| 项 | 说明 |
|---|---|
| **偏差 1** | 设计底座只落到**令牌层**。没有逐个复刻 `linear.app/DESIGN.md` 的组件规格（按钮尺寸表、表单状态表等）—— 本阶段的组件是聊天流/轨迹面板/确认卡片这三个**该 DESIGN.md 里没有的自定义组件**，只能在令牌上自己设计。这一点与计划 §1.2「界面落地走 uicraft」的定位一致。 |
| **偏差 2** | 计划里 `P5` 的通过信号包含"两个账号能登录"；本次**只真机验证了 `zhang_wei`（employee）**。HR 账号的登录在 P1 的接口验证里已经用 `wang_fang` 走过（返回 `role: hr`），且前端代码路径完全相同（同一个 `login()`），故未重复点一遍。 |
| **已知限制** | 登录页只列了 10 个可登录账号里的 5 个（其余 5 个可手输用户名）。 |
