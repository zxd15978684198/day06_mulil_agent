> 这**不是**原计划（`P0`–`P8`）里的阶段，是交付之后追加的需求：用户要求给前端增加多个主题。
> 用户的三个决定：**深色变体 + 1 套亮色**；**accent 不拆，跟着主题走**；**切换器放顶栏右侧 + 登录页各一个**。

## 2. 换肤机制：为什么组件一行都不用改

Tailwind v4 的 `@theme` 会把变量输出到 `:root`，于是 `bg-surface-1` 编译出来就是：

```css
background-color: var(--color-surface-1);
```

所以在 `html[data-theme='...']` 下覆盖这些变量，**整个界面就换肤了** —— 零重建、零组件改动。

选择器权重：`html[data-theme='x']` 是 (0,1,1)，`@theme` 输出的 `:root` 是 (0,1,0)，前者胜；而且覆盖块**不带 `@layer`**，层级上也能压过 `@theme` 那一层。

这条路径能走得通，靠的是 `P5` 当初的一个决定：**只用令牌，不写死颜色**。本次开工前的核查数据显示 —— 全前端只剩 **3 处**硬编码调色板颜色（都是 accent 按钮上的 `text-white`），其余全走令牌。这就是"当初多做一步、现在省一大截"的样本。

---

## 3. 三个颜色角色必须分开（本次最实质的设计决定）

做多主题时最容易出的错，是把"强调色"当成一个东西。实际上它有**三个互斥的角色**，浅色主题下它们的取值方向甚至是相反的：

| 令牌 | 角色 | 约束 |
|---|---|---|
| `--color-accent` | 强调色**底**（按钮背景） | 必须让 `--color-on-accent` 压得住 ≥ 4.5 |
| `--color-accent-hi` | accent 底的 **hover** | 同上 —— 它仍然是背景色 |
| `--color-accent-text` | 强调色的**文字**（链接、徽章、选中项） | 必须能在 `accent-soft` 与 `surface-1` 上 ≥ 4.5 |

审计第一轮就是在 `accent-hi on accent-soft = 4.03` 上失败的：当时它同时被当成 hover 底色和文字色用。**把 hover 底色调亮以救文字，就会让按钮上的白字垮掉** —— 两个约束方向相反，只能拆成两个令牌。同理，`on-accent` 也必须独立：白昼的 accent 是深靛蓝、午夜的 accent 是亮靛蓝，前者的字是白的、后者的字必须是深色的。

---

## 4. 亮色主题的真正难点：surface 阶梯要**反向**

深色主题的规则是"越靠前越亮"（卡片比页面亮）。亮色主题**同一条规则仍然成立**，但方向反了 —— 卡片要比页面**更白**：

| | 深色（靛蓝） | 亮色（白昼） |
|---|---|---|
| `surface-0`（页面底） | `#0b0c0e` | `#eef0f2`（浅灰） |
| `surface-1`（卡片） | `#131417`（更亮） | `#ffffff`（**最白**） |
| `surface-3`（输入框） | `#21242a`（最亮） | `#eaecef`（比卡片暗） |

如果直接照搬深色的亮度顺序，亮色下"卡片"会比页面暗，看起来像凹陷的洞。另外 `--color-*-soft` 系列（`accent-soft`、`ok-soft`、`warn-soft`、`danger-soft`）原本都是**深色专用的低饱和暗底**，亮色下必须换成高亮度版本，否则白底上会出现一块块突兀的深色方块。

## 5. 对比度审计：用运行时实测驱动修色

**方法**：在浏览器里逐主题切换 `data-theme`，用 `getComputedStyle(document.documentElement).getPropertyValue('--color-…')` 读**实际生效**的变量值，按 WCAG 相对亮度公式实算对比度。这样验的是"浏览器真的在用什么"，而不是"我以为写了什么"。

### 5.1 第一轮：5 类失败

| 主题 | 失败项 | 实测 |
|---|---|---|
| indigo | `ink-3` 在 surface-1 / 2 / 3 上 | 4.33 / 4.06 / **3.66** |
| graphite | `ink-3` 在 surface-2 / 3 上 | 4.42 / **4.00** |
| indigo、graphite | `danger on danger-soft` | 4.40 |
| daylight | `ok on ok-soft` | 4.41 |
| indigo | `accent-hi on accent-soft`（选中项与角色徽章） | 4.03 |
| midnight | — | **第一轮就零失败** |

### 5.2 修法

- **ink-3 提亮**（indigo `#8a8f98`、graphite `#8f8f97`），同时把 ink-2 一起提亮保持层级可辨 —— 因为最差的组合是 `ink-3 on surface-3`（深色主题里最亮的那层底）。
- **`danger-soft` 压暗**（`#2c1416` → `#20090b`）而不是把红色改浅：这样 `danger` 这个红仍然是它该有的样子。**优先级是保住颜色语义，改底不改字。**
- **daylight 的 `ok` 加深**（`#1a7f52` → `#177349`）。
- **新增 `--color-accent-text`**，把 6 处文字用途从 `accent-hi` 拆出来（见 §3）。

### 5.3 第二轮：四主题全部通过

| 主题 | 最差 ink 组合 | 失败数 |
|---|---|---|
| 靛蓝 | `ink-3 on surface-3` = **4.79** | **0** |
| 午夜 | `ink-3 on surface-3` = **5.74** | **0** |
| 石墨 | `ink-3 on surface-3` = **4.69** | **0** |
| 白昼 | `ink-3 on surface-3` = **4.89** | **0** |

语义对实测（全部 ≥ 4.5）：

| 组合 | 靛蓝 | 午夜 | 石墨 | 白昼 |
|---|---|---|---|---|
| `on-accent / accent` | 4.70 | 6.47 | 5.28 | 6.29 |
| `accent-text / accent-soft` | 7.33 | 11.16 | 9.10 | 6.38 |
| `accent-text / surface-1` | 8.68 | 12.45 | 10.03 | 7.90 |
| `ink-2 / accent-soft` | 5.91 | 7.40 | 5.81 | 6.46 |
| `warn / warn-soft` | 7.03 | 8.39 | 7.03 | 5.12 |
| `danger / danger-soft` | 4.85 | 6.32 | 4.85 | 4.85 |
| `ok / ok-soft` | n/a¹ | 8.70 | 6.51 | 5.17 |

¹ 见 §6 的 Tailwind tree-shaking 说明。

**判定为有意保留的一项**：`hairline-strong on surface-1` ≈ 1.55–1.76。它是**装饰性分隔线**，不承载信息，按 WCAG 1.4.11 不属于"必须 3:1 的 UI 组件边界"。整套界面的视觉规则就是"用发丝边框分层"，把它压到 3:1 会让每个卡片都镶一圈刺眼的边。

## 6. 防闪烁（FOUC）：唯一必须写的非 React 代码

主题必须在 **React 挂载之前**就写到 `<html data-theme>` 上，否则每次刷新都会先闪一下默认主题。做法是在 `frontend/index.html` 的 `<head>` 里放一段同步内联脚本。

**代价必须说清楚**：这段脚本跑在打包产物之外，没法 `import` `src/lib/theme.ts`，所以 `STORAGE_KEY` 与主题候选列表在**两处各有一份拷贝**。这是本次唯一的重复，两边的注释里都写明了"改一处必须改另一处"。

**验证**：把 localStorage 设成 `daylight` 后重新进入页面，在 `DOMContentLoaded` 时刻（React 的模块脚本此时尚未执行）读到的 `data-theme` **已经是 `daylight`**，切换器标签同时显示「◐ 白昼」。

另：`color-scheme` 每套主题各自设置（深色三套 `dark`、白昼 `light`），它管滚动条、`<details>` 的三角标、原生输入框控件 —— 不跟着切的话亮色主题下这些还是深色的。

## 7. 切换器

`ThemeSwitcher` 出现在**对话页顶栏右侧**（与「退出登录」并排）和**登录页右上角**（未登录也能换 —— 演示时可以先选主题再登录）。

无障碍：按钮 `aria-haspopup="listbox"` + `aria-expanded` + 有意义的 `aria-label`；下拉是 `role="listbox"`，每项 `role="option"` + `aria-selected`；支持 Escape 与点击外部关闭。

**刻意不做色块预览**：色值只存在于 CSS 里，想画预览就得在 TS 里再抄一份十六进制 —— 那是第二处重复维护点。改用一句话文字说明（如"纯黑 · 高对比"）。

## 9. 偏差与已知项

| 项 | 说明 |
|---|---|
| **Tailwind v4 tree-shaking** | 未被任何 utility 使用的主题变量会被移除。默认主题写在 `@theme` 里，其中 `--color-ok` 从未被用到，所以运行时读到**空字符串**（审计里 `ok/ok-soft = null`）。午夜/石墨/白昼三套写在普通 CSS 块里，不受影响。**只影响未被使用的令牌，UI 无影响**；真要用 `bg-ok` 时 Tailwind 会连同变量一起保留。 |
| **未做** | "跟随系统 `prefers-color-scheme`" —— 用户选择的是四套显式主题，没有 auto 档。 |
| **未做** | accent 作为独立维度（用户明确选择不拆）。 |
| **沿用** | 单包 > 500 kB 的构建警告（`react-markdown` + `remark-gfm` + `motion`），与主题无关，见 `P8_流程文档.md` §5。 |
| **对比度不是一次性工作** | 本次审计覆盖的是**令牌两两组合**。真实 DOM 里如果将来有人在某个组件上直接写调色板颜色（像当初那 3 处 `text-white`），审计就漏了。保持"只用令牌"这条纪律，审计才继续有效。 |

## 10. 复现方式

```bash
cd frontend && npm run dev     # → http://localhost:5173
```

1. 登录页右上角点「靛蓝」→ 依次切四套主题，观察整页换肤（含滚动条、输入框、下拉）。
2. 选「白昼」→ 刷新页面 → **不应看到深色一闪**。
3. 进对话页 → 顶栏右侧同样有切换器，切换后主题仍然持久。

审计脚本的口径（如需重跑）：逐主题 `setAttribute('data-theme', id)`，读 `--color-*` 计算 WCAG 比值，阈值 4.5。
