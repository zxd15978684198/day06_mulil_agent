## 3. 三栏的职责划分

| 栏 | 宽度 | 显示条件 | 职责 |
|---|---|---|---|
| 左 · 身份与能力 | 240px | ≥1280px（`xl`） | 这个身份能做什么 + 示例问题 |
| 中 · 对话 | 自适应（内容列 768px） | **始终** | 消息流 + 输入框 |
| 右 · 本轮轨迹 | 320px | ≥1280px（`xl`） | 最新一轮的 Agent 路由与业务 Tool，**默认展开** |

**窄屏（<1280px）自动收回单栏** —— 右栏消失后轨迹回到每条回答下方的折叠面板；左栏的信息（身份/角色）由顶栏的徽章承担。所以功能没有任何损失，只是呈现方式随宽度变。

### 3.1 左栏不只是"填空"，它把权限闸门摆到了台面上

三个能力卡片里，`HR 审批` 对员工身份是**灰显 + 标注「需要 HR 身份」**的。这一栏的事实来源是 `CLAUDE.md` 的架构图（Supervisor 只挂 Agent Tools、专家各持自己的业务 Tool、`ask_hr_agent` 只对 HR 可见）。

演示时不用讲"我们有三道权限闸门"—— 换个账号登录，侧栏自己会说话。

### 3.2 右栏与气泡下面板的分工（用户选择"两者都留"）

| | 右栏 | 气泡下的折叠面板 |
|---|---|---|
| 看哪一轮 | **只有最新一轮** | 每一轮各一份 |
| 默认状态 | **展开** | 折叠 |
| 用途 | 实时可见 —— 演示时"点一下才看得见"是最大的摩擦 | 可追溯 —— 回翻历史 |

两者职责不同，冗余是可接受的成本。

### 3.3 `bare` 模式：修掉一处视觉重复

第一版右栏直接复用了 `<TracePanel defaultOpen />`，结果界面上出现了**两层边框**和**两遍摘要**（右栏自己的"专家 / 业务 Tool"行 + 面板的"调用了 N 个 Agent Tool"）。

修法：给 `TracePanel` 加 `bare` 开关 —— 为真时只渲染条目本身，不要外层 `<details>` 与摘要行。右栏改用它之后，摘要只由右栏自己那一份承担。

实现细节：`defaultOpen` 用**受控 `open` + `onToggle` 跟踪**，而不是把常量直接传给 `open`。否则每次重渲染 React 都会把用户的折叠操作掰回去。

## 4. 验证证据

### 4.1 1920px（三栏）

```json
{
  "viewport": 1920,
  "asides": [{ "w": 240, "visible": true }, { "w": 320, "visible": true }],
  "centerW": 1360
}
```

左栏内容断言：`hasCapabilityHeading: true`（出现"这个身份能做什么"）、`hasExamples: true`（出现"试试这样问"）、`hrRowLocked: true`（员工身份下出现"需要 HR 身份"）。

右栏内容断言：标题"本轮轨迹"、`专家 → ask_employee_service_agent`、`业务 Tool → list_requestable_devices`，且轨迹默认展开。

**示例问题**：点「公司的年假是怎么规定的？」→ 输入框值变为该文本、焦点落在 `TEXTAREA`（`composerValue: "公司的年假是怎么规定的？"`、`focused: "TEXTAREA"`）。只填不发，符合"点一下只填进输入框，你可以改完再发"的提示。

{ "viewport": 1100, "asides": [{ "w": 0, "visible": false }, { "w": 0, "visible": false }], "centerW": 1100 }

两侧栏 `display: none`，中栏吃满全宽。

## 5. 偏差与已知项

| 项 | 说明 |
|---|---|
| **中栏内容仍是 768px** | 这是有意保留的：正文约 85–90 字符/行已经到可读性上限，再放宽只会更难读。宽屏下左右两侧的空隙从"内容没撑开"变成了"两个侧栏之间的呼吸空间" —— 有边框锚住之后，同样的空白不再显得突兀。 |
| **`tsc` 拦下一处** | `SessionPanel.tsx` 里定义了 `ROLE_LABEL` 却没用（改用 `isHr` 判断），`noUnusedLocals` 直接报 `TS6133`。已删。 |
| **未做** | 左栏/右栏宽度不可拖拽调节；没有做"侧栏折叠"按钮（窄屏自动隐藏已经覆盖主要场景）。 |
| **与 P8 验收清单的关系** | P8 §2.1 的八个主场景在本布局下**全部仍然成立**（登录/对话/轨迹/确认/取消/刷新/退出/409），本次只改呈现层，没有动任何数据流与契约。 |

## 6. 复现方式

```bash
cd frontend && npm run dev     # → http://localhost:5173
```

1. 浏览器拉到 **≥1280px**：出现左右两栏。左栏切到 HR 账号（`wang_fang`）后「HR 审批」不再灰显。
2. 点左栏的示例问题 → 只填进输入框，不自动发送。
3. 发一条会路由的消息（如「公司的年假是怎么规定的？」）→ **右栏立刻显示本轮路由链**，不用点开任何东西；同时回答下方的折叠面板也保留一份。
4. 把窗口拉到 **<1280px**：两侧栏消失，回到单栏。
