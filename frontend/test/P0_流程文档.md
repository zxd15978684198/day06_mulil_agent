## 2. `C1` 实测：`trace` 是线程累计轨迹（本阶段最关键的一条）

同一 `session_id` 连发三轮，观察 `AgentReply.trace.length`：

| 轮次 | 请求 | `trace.length` | 内容 |
|---|---|---|---|
| A | `你好` | **0** | `[]` |
| B | 申请一台显示器（带申请理由） | **1** | `[agent_tool_calls: ask_employee_service_agent]` |
| C | `POST /api/confirmation {approved:true}` | **2** | `[agent_tool_calls: …（与 B 完全相同）, agent_tool_result: ask_employee_service_agent]` |

**结论**：`trace` **前缀稳定、只追加、永不收缩**。

- 所以 `K1`（"每轮把返回的 trace 直接 append"）会让第 N 轮出现 N 份重复条目 —— 这是真的坑。
- 所以 `R1` 的解法成立：前端记 `prevLen`，本轮只渲染 `trace.slice(prevLen)`。
- 附带实测到的两个字段事实：中断轮 `answer` 是 `null`（`K8`）；`agent_tool_result.content` 是**一个 JSON 字符串**，内层业务 Tool 名要 `JSON.parse` 后取 `business_tools` 才能拿到。

## 5. 本阶段踩到的坑（都已解决，写在这里避免重踩）

1. **TypeScript 6.0.3 废弃 `baseUrl`** → 加了会直接 `error TS5101: Option 'baseUrl' is deprecated`，`tsc -b` 退出码 2，构建根本不进 Vite。改法：只用 `paths`（TS 4.1+ 会相对 tsconfig 文件解析），删掉 `baseUrl`。
2. **`registry.npmjs.org` 直连会"挂着不返回"**，不快速报错。表现是 `npm install` 卡住数分钟，最后给 `If you are behind a proxy, please make sure that the 'proxy' config is set properly`。改法：`--registry=https://registry.npmmirror.com`，`added 17 packages in 20s`。
3. **Vite 8 dev server 绑的是 `localhost`，不是 `127.0.0.1`** → 用 `127.0.0.1:5173` 探测会得到"连不上"的假阴性；用 `http://localhost:5173/` 探测才 200。
4. **`Start-Process uv` 杀掉父进程不会杀掉 python 子进程** → 端口一直被占。清理必须按端口杀：`Get-NetTCPConnection -LocalPort <p> -State Listen` → `Stop-Process`。
5. **代理 502 ≠ 代理配错**：第一次测代理时我只等 Vite 就绪、没等后端就绪，于是 Vite 拿不到 8000 → 502。先后端 `GET /` 返回 200、再测代理，就 200 了。
